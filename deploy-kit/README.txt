============================================================
  泛微 ecology 二开部署工具包  使用说明
============================================================

本说明共十节，可按需跳读。安装过程全部通过 install.bat 的
交互菜单完成，无需记忆命令行参数。

------------------------------------------------------------
一、工具包用途
------------------------------------------------------------
把开发机打包好的二开文件（class、jsp、配置文件、jar 包等）
安全地安装到 ecology 服务器，并做到：

  - 安装前自动备份旧文件，备份可回滚；
  - 安装后逐个文件做 SHA256 校验，确保复制完整；
  - 全程写详细日志，出问题可追溯、可手工逆向；
  - 提供审计模式，随时核对线上文件与包内清单是否一致。

适用对象：泛微 ecology 二次开发的部署人员、运维人员。

------------------------------------------------------------
二、目录结构
------------------------------------------------------------
zip 解压后得到的文件夹内容如下：

  install.bat        安装/审计/回滚 一体脚本（双击即用）
  README.txt         本说明
  manifest.txt       文件清单 + SHA256 校验和（勿手工改）
  files\             待安装的文件（按 ecology 根目录结构摆放）
  禁止直接在压缩包中运行install.bat-请先解压.txt
                     空文件，仅借文件名提示必须先解压

安装/审计/回滚运行后还会生成：

  logs\deploy_<时间戳>.log      当次操作详细日志（所有模式都写）
  logs\verify_fail_<时间戳>.txt 审计失败清单（仅审计有失败时）

另外安装模式会生成：

  _backup\<时间戳>\  当次安装的旧文件备份（保留原目录结构）
                     另含 _manifest.txt（当次清单副本）
                     与 _newfiles.txt（当次新增文件清单，仅在
                     有新增文件时生成；回滚据此删除）

注意：备份不再放在 ecology 根目录下，统一放在本解压目录的
_backup\ 内，避免备份文件被 ecology 扫描影响服务启动。

------------------------------------------------------------
三、本地打包步骤（开发机）
（本节仅开发机适用；服务器上只需 install.bat，用不到打包脚本）
------------------------------------------------------------
在开发机上用 PowerShell 运行 New-DeployPackage.ps1：

  .\New-DeployPackage.ps1 -SourceRoot <编译输出根> `
      -MapFile .\maps\<清单文件>.map -Name <包名>

  -SourceRoot  源文件根目录（如 out\production\XxxModule）
  -MapFile     清单，每行 "源相对路径 => 包内相对路径"
  -Name        包名，用于 zip 文件名
  -OutDir      可选，zip 输出目录（默认仓库 deploy\）

产出 <包名>-<时间戳>.zip，即可拷到服务器。

安全约定：只打包清单里显式列出的文件，绝不通配符自动抓，
防止误打入 wecom.properties 等含敏感信息的文件。

打包脚本内建校验：清单行格式（=> 或制表符分隔）、目标路径必须
相对且不含 ..、不得与随包文件（install.bat / README.txt /
manifest.txt）重名、目标路径去重、源文件必须在源根内、源文件
存在；传非默认 -OutDir 时会打印黄色确认提示。

清单文件须保存为 UTF-8 编码（记事本另存为时选 UTF-8）：
脚本按 UTF-8 读取清单，若用 GBK 保存，中文路径会变乱码导致
"源文件不存在"。

------------------------------------------------------------
四、服务器安装步骤
------------------------------------------------------------
1. 把 zip 拷到服务器，解压到一个独立文件夹
   （如 D:\temp\<包名>\）。切勿在压缩软件里直接双击
   install.bat —— 必须解压后再运行。

2. 双击 install.bat，进入交互菜单：

     [1] 安装部署    [2] 审计模式    [3] 回滚
     [h] 帮助        [m] 主菜单      [q] 退出

3. 输入 1 进入安装：
   - 若清单含 jar 包，先弹警告，需输入 yes 确认
     ecology 服务已停止，否则中止；
   - 输入 y 回车 = 用默认路径 D:\WEAVER\ecology；
     或直接粘贴自定义 ecology 根目录完整路径；
   - 若清单含 2 个及以上 jar（批量 jar），强制手动
     输入路径，不接受默认值。

4. 安装过程自动完成：装前自检（逐个核对包内文件与
   manifest 是否一致，不一致立即中止、不动目标文件）→
   备份旧文件 → 复制新文件 → 逐个 SHA256 校验。结束后
   屏幕回显最近日志并打印日志完整路径。

5. 安装结束务必按提示重启 ecology 服务（见第六节）。

全程请勿点窗口右上角 X 关闭，用 q 退出。

------------------------------------------------------------
五、审计模式
------------------------------------------------------------
作用：不改动任何文件，只核对线上文件与 manifest.txt 是否
一致，用于部署后复核、或怀疑线上文件被改时排查。

进入方式：主菜单输入 2，输入 y 用默认路径或粘贴自定义路径。

结果：每个文件显示 [OK]/[FAIL]，末尾汇总。若有失败，
失败清单会单独写入 logs\verify_fail_<时间戳>.txt，
可直接发给开发人员。

审计结束输入 b 返回主菜单，输入 q 退出。

也可命令行调用（供脚本/Agent 自动化）：
  install.bat <ecology根> /verify     退出码 0=全过 1=有失败

从 Git Bash 调用时，/verify 会被 MSYS 改写成路径，须写成整体
加引号的形态：
  MSYS2_ARG_CONV_EXCL='*' cmd /c "install.bat <ecology根> /verify"
（不加引号 bash 会先吃掉路径里的反斜杠；cmd/PowerShell 内无此问题）

------------------------------------------------------------
六、重启提醒（重要）
------------------------------------------------------------
安装或回滚后，必须重启 ecology 服务，否则新代码不生效。

原因：Jersey 在 webapp 启动时扫描 com.cloudstore / com.api
包。只拷贝类文件而不重启，新接口会一直返回 404。

重启命令示例（服务名以 services.msc 中实际名称为准）：
    net stop "ecology"
    net start "ecology"
或打开 services.msc，找到 ecology 服务后右键重启。

------------------------------------------------------------
七、回滚方法
------------------------------------------------------------
回滚 = 把某次安装前的旧文件恢复回去，并删除当次新增文件。

进入方式：主菜单输入 3。

步骤：
  1. 屏幕列出 _backup\ 下所有回滚点（按时间倒序，最新在前）；
  2. 输入要回滚的序号；
  3. 输入要恢复到的 ecology 根目录；
  4. 工具把该备份点的旧文件覆盖回去；
  5. 列出当次"新增"的文件，输入 yes 确认后删除
     （不确认则保留，便于只回退修改、保留新增）。

回滚全程写日志（动作类型 ROLLBACK）。回滚后同样需重启
ecology 服务。

手工回滚备选：直接到 _backup\<时间戳>\ 按原相对路径把文件
拷回 ecology 根，再删除 _newfiles.txt 里列出的新增文件。

------------------------------------------------------------
八、编码与兼容性说明
------------------------------------------------------------
  - install.bat 为 GBK（ANSI 936）+ CRLF 行尾，双击在
    中文 Windows 控制台正常显示；请勿用记事本另存为 UTF-8。
  - manifest.txt 为 UTF-8 无 BOM + LF，由打包脚本生成，
    请勿手工编辑（改一个字符都会导致校验失败）。
  - 日志文件为 GBK，可用记事本直接打开。
  - 随包的 README.txt / maps\*.map 为 UTF-8 无 BOM；map 用记事本
    编辑后须另存为 UTF-8，否则中文路径会乱码。
  - 兼容 Windows Server 2012 R2 及以上；install.bat 为纯批处理，
    不依赖 PowerShell。
  - 脚本无法禁用窗口关闭按钮，请在菜单底部提示下用 q 退出，
    不要点窗口右上角 X。

------------------------------------------------------------
九、技能首次调用与路径配置（仅开发机适用）
------------------------------------------------------------
本工具包配套的 deploy-ecology-full / deploy-ecology-increment
两个技能，首次被 AI 代理调用时会在 deploy-kit\ 下生成
deploy-config.json，其中只记录一项：

  - ecology 安装根（ecologyRoot.path）——本机的部署目标
    （测试 / 演练用），另带 mode 与 confirmed 标记。
    正式服务器根不走这个文件，由安装前的确认门显式确认。

     同目录下的 projects.md 是项目登记表（项目 | 源根 |
     基线清单 | 输出目录 | 部署物构成 | 最近部署），同样由
     技能首次注册项目时生成。

两个文件都含本机真实路径与项目名，均已在 .gitignore 中忽略，
不纳入版本控制、不随仓库发布。删除后下次调用技能时会重新
引导配置。

------------------------------------------------------------
十、常见问题
------------------------------------------------------------
Q1 双击 install.bat 闪退？
   多半是文件被改成 UTF-8 或行尾变 LF。重新解压 zip，
   或从开发机重新拷贝原始 install.bat。

Q2 提示"缺少 manifest.txt / files 目录"？
   说明不在解压后的包根目录运行。请进入解压出的文件夹
   再双击 install.bat。

Q3 某个文件 [FAIL] 校验不一致？
   复制被占用或被杀毒拦截。确认 ecology 已停止、关闭占用
   该文件的程序后重跑安装；备份在 _backup\ 不会丢。

Q4 jar 替换后服务起不来？
   多是替换时服务未停止导致 jar 损坏。用回滚（菜单 3）
   恢复到上一备份点，确认服务停止后再重新安装。

Q5 想确认线上文件和包内一致？
   用审计模式（菜单 2 或 install.bat <根> /verify）。

Q6 备份占用空间越来越大？
   _backup\ 下每个时间戳目录是一次完整备份。确认系统稳定
   后，可手工删除较早的时间戳目录。
