# deploy-ecology-skills

泛微 ecology（E9，Windows 服务器，classbean 部署方式）二开代码部署的 ZCode 技能包：
两个部署技能 + 一套打包 / 安装 / 校验工具。

目标：把「改代码 → 打包 → 部署 → 校验 → 回滚」变成一条可重复、可验证的固定流程。

---

## 面向开发者

### 它解决什么问题

在 ecology 上部署二开代码，常见做法是手工拷贝文件。手工做法有五个典型问题：

1. **漏文件。** 内嵌类（`Xxx$Inner.class`）和配置文件（`.properties`）最容易漏，漏一个功能就坏一块。
2. **说不清装了什么。** 没有记录和校验，事后无法证明服务器上是哪个版本。
3. **不敢打包。** 用通配符抓文件，可能把 `wecom.properties` 这类含密钥的文件打进部署包。
4. **难回滚。** 覆盖前没有备份，出问题只能凭记忆恢复。
5. **忘记重启。** ecology 的 Jersey 框架只在服务启动时扫描 `com.cloudstore;com.api` 包。
   拷了类文件不重启，新接口永远返回 404。

本项目把这五件事变成流程里的固定环节。

### 它提供什么能力

两个技能，覆盖从测试到生产的完整路径：

1. **测试环境迭代**（`deploy-ecology-increment`）：每轮只打包本轮变更的文件，装进本机测试
   ecology，装完全量可证。
2. **正式环境上线**（`deploy-ecology-full`）：把项目的完整文件基线打成全量包，一次性迁移到
   正式服务器。安装前有确认门，安装后有审计。

每次部署执行同样的固定动作：

```
写清单 → 打包（逐文件算 SHA256）→ 假根演练（全量流程交付前必过）
      → 安装（备份 → 复制 → 逐个复核哈希）→ 复核（/verify 审计 + 接口探针）
      → 回写（增量：基线清单 / 全量：项目登记表的「最近部署」）
```

### 核心价值

- **可证部署**：部署包里每个文件带 SHA256。安装后逐个复核，哈希对不上即失败（退出码 1）。
  不存在"以为装好了"。
- **零泄漏**：只打包清单里显式列出的文件，绝不用通配符，含密钥文件不会误入包。
- **可回滚**：每次安装先把旧文件备份到解压目录的 `_backup\<时间戳>\`，可用 install.bat
  菜单一键回滚（含当次新增文件删除），回滚全程写日志。
- **全程留痕**：安装 / 审计 / 回滚的每个动作写入 `logs\deploy_<时间戳>.log`
  （含时间 / 动作 / 源路径 / 目标路径），可据此手工逆向。
- **菜单化操作**：服务器端双击 install.bat 即出交互菜单（安装 / 审计 / 回滚 / 帮助 / 退出），
  无需记命令行参数；含 jar 时强制确认服务已停止，批量 jar 强制手动输路径。
- **可演练**：在纯 ASCII 目录（如 `C:\Temp\`）用假源根 + 假 ecology 根走完整流程——含
  篡改检出（改一个文件后 `/verify` 必须退出码 1），不碰真实环境。
- **对 Agent 友好**：流程固化为技能，每步带完成标准，由 ZCode 会话按步骤执行。
- **实战打磨**：流程来自真实的 ecology 二开部署迭代，配套脚本经假根全流程演练验证。

### 功能清单

配套工具都在 `deploy-kit\`：

| 工具 | 功能 |
|---|---|
| `New-DeployPackage.ps1` | 本地打包：按显式清单收集文件、重算 SHA256、生成可直接拷到服务器的部署包（包内自带安装脚本、说明与解压提示文件） |
| `install.bat`（双击） | 交互菜单：安装 / 审计 / 回滚 / 帮助 / 退出，安装含备份 + 逐个 SHA256 复核 + 写日志 |
| `install.bat <ecology根>` | 命令行安装（供脚本 / Agent 自动化），退出码 0 全过 / 1 有失败 |
| `install.bat <ecology根> /verify` | 审计模式：只校验、不复制，随时核对服务器文件与清单是否一致 |
| `deploy-kit\maps\` | 部署清单目录：含 2 份虚构样例（订单台账），演示清单格式与"内嵌类 / properties 必列"的写法 |
| `deploy-kit\projects.md` | 项目登记表（本机文件，首次注册项目时生成；含真实项目名与路径，已 gitignore、不进仓库） |

### 压缩包怎么用（部署到服务器）

打包产出的是 `<包名>-<时间戳>.zip`，它自包含安装所需的全部内容：

```
install.bat        双击即用（菜单化）
README.txt         使用说明
manifest.txt       文件清单 + 校验和
files\             待安装文件
禁止直接在压缩包中运行install.bat-请先解压.txt   提示空文件
```

使用步骤（人工作，三步）：

1. **解压**：把 zip 拷到服务器，解压到一个独立文件夹（如 `D:\temp\<包名>\`）。
   切勿在压缩软件里直接双击 install.bat —— 包内已放一个提示文件以防误操作。
2. **运行**：进入解压出的文件夹，双击 `install.bat`，按菜单操作：
   输入 `1` 安装、`2` 审计、`3` 回滚、`h` 帮助、`m` 主菜单、`q` 退出。
   - 安装时输入 `y` 用默认路径 `D:\WEAVER\ecology`，或粘贴自定义 ecology 根路径；
   - 清单含 jar 时先确认服务已停止（输 `yes`），批量 jar 强制手动输路径。
3. **重启**：安装 / 回滚完成后按屏幕提示重启 ecology 服务，否则新代码不生效。

备份在解压目录的 `_backup\`、日志在 `logs\`，都不在 ecology 根目录下，不影响服务启动。

### 适用场景与边界

**适用：**

- 泛微 ecology E9，Windows 服务器，classbean 部署方式。
- 部署物为 class / properties / JSP / 静态资源 / WEB-INF 白名单。
- 需要"测试环境迭代 → 正式环境全量迁移"的标准路径。

**不适用：**

- Linux 服务器、容器化部署、支持热加载的框架。
- 非 ecology 项目。
- 代码版本管理（本项目只管部署这一段）。

### 开始使用

安装只需把 `.agents\` 与 `deploy-kit\` 两个目录复制进你的项目工作区根目录。
首次调用技能时，会弹出一次选择栏确认 ecology 安装根路径；确认后不再询问。

更快的方式：把本仓库路径直接发给 AI 代理，让它自动完成安装（见下节"面向 Agent"）。
完整安装步骤、使用前提、安全红线、FAQ、回滚见 [README-安装说明.md](README-安装说明.md)。

## 面向 Agent（AI 代理）

本节写给 AI 代理：用户把本仓库路径（或 GitHub 地址）发给你后，你应能据此自动完成
技能安装与首次初始化引导，并在后续对话中指导用户使用部署压缩包。

### 仓库识别

- 本仓库是 ZCode 技能包，技能入口为 `.agents\skills\<技能名>\SKILL.md`。
- 两个技能均标记 `disable-model-invocation: true`：**仅手动触发**。代理不自行调用技能；
  应把技能名告诉用户，由用户点名调用。
- 配套工具在 `deploy-kit\`：打包脚本、服务器安装脚本、部署清单目录（含虚构样例）。

### 用户给你项目路径后：自动安装技能（引导话术）

当用户把本仓库的本地路径或 GitHub 地址发给你，并希望你帮他装上这套部署技能时，
按下面的引导推进（全程用 AskUserQuestion / 对话确认，每一步给出推荐答案）：

1. **确认工作区**：问用户"要把技能装进哪个项目工作区？"给出推荐——用户当前打开的
   项目根目录（推荐）。拿到工作区根路径后进入下一步。
2. **复制两个目录**：把本仓库的 `.agents\` 与 `deploy-kit\` 复制进该工作区根：

   ```powershell
   Copy-Item -Recurse -Force <本仓库>\.agents, <本仓库>\deploy-kit <工作区根>\
   ```

   `.agents\skills\` 是 ZCode 的技能发现路径，必须位于工作区根目录下。
3. **补忽略规则**：检查 `<工作区根>\.gitignore`，缺则追加两行——`deploy-kit/deploy-config.json`
   与 `deploy/`（本仓库的 `.gitignore` 不会随复制而来）。**完成判定**：
   `git check-ignore -v deploy-kit/deploy-config.json` 有输出。
4. **验证安装**：确认以下两个文件存在；并提示用户重启 ZCode 会话后技能出现在技能列表：

   - `<工作区根>\.agents\skills\deploy-ecology-increment\SKILL.md`
   - `<工作区根>\.agents\skills\deploy-ecology-full\SKILL.md`

   若同名技能已装在用户级 `~\.agents\skills\` 下，两份会同时被系统列出——告知用户生效的是
   工作区副本，并把用户级旧副本同步或删掉，避免陈旧版本被执行。
5. **引导首次初始化**：见下一节，仅一次。

### 首次初始化引导（安装后必做）

安装完成后，不要直接开始部署。先让用户完成一次路径确认：

1. 请用户调用任一技能，例如输入技能名 `deploy-ecology-increment`。
2. 技能首次运行会弹出选择栏，询问 ecology 安装根用哪种路径：

   | 选项 | 取值 |
   |---|---|
   | 本机 ecology 安装根（推荐） | `D:\WEAVER\ecology`——ecology 默认安装目录 |
   | 自定义安装根 | 用户自定义的安装目录，保存后跨调用复用 |

   登记的根是**本机的部署目标**（测试 / 演练用）。本机若同时装着生产 ecology，两个根必须
   分开确认，不得把生产根登记为部署目标。

3. 用户确认后，技能写入 `<工作区根>\deploy-kit\deploy-config.json`。
4. **完成判定**：该文件存在且含 `"confirmed": true`。此后所有调用直接读取配置，不再询问。

说明：`deploy-config.json` 是本机状态，含真实路径，不要提交到版本库（见上一步的忽略规则）。
每个工作区副本初始化一次。

### 指导用户使用部署压缩包（对话话术）

当技能产出部署 zip、或用户拿到一个 zip 不知道怎么用时，在对话里这样指导：

> 这个 zip 是自包含的部署包，用三步就能装上：
>
> 1. **先解压**：把 zip 拷到服务器，解压到一个独立文件夹（比如 `D:\temp\包名\`）。
>    注意不要在压缩软件里直接双击 install.bat，包里的 `禁止直接在压缩包中运行install.bat-请先解压.txt`
>    就是提醒这一点，一定要先解压。
> 2. **双击 install.bat**：进入解压出的文件夹双击它，会出现菜单——
>    输入 `1` 安装、`2` 审计、`3` 回滚、`h` 帮助、`m` 主菜单、`q` 退出。
>    安装时输入 `y` 用默认路径 `D:\WEAVER\ecology`，或粘贴你的 ecology 根路径；
>    如果包里有 jar 包，它会先让你确认服务已停止（输 `yes`）。
> 3. **重启服务**：装完后按提示重启 ecology 服务（`net stop "ecology"` 再
>    `net start "ecology"`），不重启新代码不生效。
>
> 备份在解压目录的 `_backup\`，日志在 `logs\`，想反悔就用菜单里的回滚。

## 运行环境

- Windows + PowerShell 5.1（打包脚本）；`certutil`（系统自带，用于 SHA256 校验）。
- 服务器端只需 `install.bat`：菜单、日志、回滚、装前自检全部为纯批处理，不依赖 PowerShell 或任何外部组件。
- 编译步骤使用你现有的编译方式（示例：IDEA MCP `build_project`）；本项目不绑定具体 IDE。
