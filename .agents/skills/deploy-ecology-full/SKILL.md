# ecology 二开全量部署（指定项目 → 正式环境）

把一个项目功能的完整文件基线一次性迁移到正式环境。与增量迭代
（[deploy-ecology-increment](../deploy-ecology-increment/SKILL.md)）的分工：
迭代在测试环境小步走，功能定稿后走本流程整体上生产。

## 命令行调用约定（先读）

本技能常在 Git Bash 里执行，而 MSYS 会把 `/verify` 这类以 `/` 开头的参数改写成路径
（`cmd /c install.bat` 本身也会被吃掉）。从 Git Bash 调用一律写成整体加引号的形态：

```bash
MSYS2_ARG_CONV_EXCL='*' cmd /c "install.bat <ecology根> /verify"
```

（整体加引号是必须的：不加引号时 bash 会先吃掉路径里的反斜杠。）在 cmd / PowerShell 里
直接运行 install.bat 无此问题。下文各步骤的 `install.bat` 命令均按此形态执行。

## 项目档案（本机文件，不进仓库）

项目登记表在 **`deploy-kit\projects.md`**——本机文件：含真实项目名与真实路径，已进
`.gitignore`，不随仓库发布、不随技能分发。**本技能文件是公开仓库的发布物，任何真实项目名、
真实路径、服务器信息都不得写进本文件**；项目相关的数据一律只落 `deploy-kit\` 下的本机文件。
表列六项：项目 | 源根（编译产物） | 全量基线清单 | 输出目录 | 部署物构成 | 最近部署。

新项目注册：按步骤 1 生成并定稿基线清单，登记四项（源根、基线路径、输出目录、部署物构成）
并与用户确认；基线清单落盘 `deploy-kit\maps\`，同时把该项目一行写进
`deploy-kit\projects.md`（文件不存在则按上列建表头后写入）。两处都落盘才算注册完成。
「输出目录」是项目预先指定的打包产物最终留档处（约定默认 `<项目工作区>\deploy\`），一经
登记即固定；打包与假根演练在纯 ASCII 演练目录进行（见步骤 3/4），通过后把产物拷回它。

## 步骤 0：路径配置（仅首次调用，之后自动跳过）

本步登记**本机** ecology 安装根：两个技能共用这一份配置（供本机测试与演练定位），登记后
不再询问；正式服务器根由第 6 步确认门显式确认，不读它。**登记的根是本技能在本机的部署
目标**——若这台机器上同时装着一套生产 ecology，两个根必须分别确认，**不得把生产 ecology
根登记为部署目标**。

读 `deploy-kit\deploy-config.json`：

- **已存在且 `"confirmed": true`** → 直接进入下一步。
- **不存在或未确认** → 用 AskUserQuestion 弹出选择栏，询问 ecology 安装根用哪种路径：

  <!-- 下表与 deploy-ecology-increment 步骤 0 的表逐字一致；改动请同步另一技能 -->
  | 选项 | 取值 |
  |---|---|
  | 本机 ecology 安装根（推荐） | `D:\WEAVER\ecology`——ecology 默认安装目录，多数机器即此值 |
  | 自定义安装根 | 用户指定一个 ecology 安装根，保存后跨调用复用 |

  用户确认后写入以下配置（首次确认即由本流程生成该文件；用户取消则不写、中止流程，下次
  调用仍会询问）：

  ```json
  {
    "version": 1,
    "confirmed": true,
    "confirmedAt": "YYYY-MM-DD HH:mm",
    "ecologyRoot": { "mode": "server-default", "path": "D:\\WEAVER\\ecology" }
  }
  ```

  `ecologyRoot.mode` 二选一：`server-default`（`path` 固定 `D:\WEAVER\ecology`）或
  `reusable`（`path` = 用户指定的安装根）；读取时只用 `ecologyRoot.path`。

**完成标准：配置存在且 `confirmed: true`。**

## 步骤

### 1. 核对基线完整性

**执行顺序：先编译（步骤 2）再回来清点本步**——本步「对照源根实际文件」指的是本次编译的
输出；在上一轮的旧产物上清点，会把本轮已删除的类当成部署物，首次注册更会定稿一份错的基线。

全量包的正确性 = 基线清单 == 项目全部部署物。基线清单不存在时，本次按 `deploy-kit\projects.md`
中该项目的"部署物构成"生成草稿并逐行 review 定稿，存为档案中的基线路径（头部按样例形态写：
源根 / 变更摘要 / 覆盖既有）。已存在时逐类核对：

- **classbean**：源根下该项目包路径下全部 class（**含内嵌类 `Xxx$Inner.class`**）
  与 properties——对照源根实际文件清点，漏一个就是生产上少一个类；
- **mobile**：项目全部 JSP/静态资源；
- **WEB-INF**：安全白名单 XML（如有）。

两条铁律：

- **逐个枚举**：照抄整目录会把 wecom.properties 等含密钥文件打进包，每个文件逐行列出。
- **新增须 review**：基线外发现的新文件先人工 review，确认属于本项目再并入。

两类逐项核对：

- **覆盖既有文件**：属于服务器上已有文件的条目（依据历轮部署包的 manifest.txt 或用户确认），
  先在版本库里 diff 本次改动，确认改动范围可控；清单头部「覆盖既有」行逐条列名（无则写"无"）
  ——步骤 6 确认门第 2 项按它复述。
- **配置环境适配**：properties 类文件逐项核对环境相关值（库名、角色解析方式、路径）——
  确认环境自适应，或列出需在正式环境变更的项并与用户确认。

**完成标准：classbean 与源根实际文件集合一一对应（差集为空）；三类（classbean / mobile /
WEB-INF）各给出文件数，为空的一类说明判定依据；每个条目都能定位到真实来源文件（来源可
不止一处，见步骤 3）；「覆盖既有」条数明确（可为 0）且已在清单头部逐条列名；配置环境适配
的需变更项（可为 0）已与用户确认。**

### 2. 编译

全量包必然含 class：用你的编译方式（如 IDEA MCP `build_project`）编译。
**完成标准：编译成功、无 error（有 warning 则逐条记进步骤 10 报告），且打包所用产物即本次
编译输出（陈旧 class 视为未完成）。**

### 3. 打全量包

`-SourceRoot` 按来源形态二选一：

- **单一源根**：编译产物目录里已含全部部署物，直接用它；
- **来源分散（常见）**：JSP 等只在源码树、编译产物目录里没有 `mobile\`——先按 ecology
  **目标布局**（`classbean\`、`mobile\`、`WEB-INF\`）组装**暂存目录**，以暂存目录作
  `-SourceRoot`。组装脚本要可重复执行，与基线清单同目录留档（清单可由它一并生成与核对）；
  暂存目录身份与各类文件真实来源写进清单头部的「源根」字段（形态见 maps\ 样例）。

打包前刷新产物：class 用本次编译输出；生成型产物（由脚本/构建管线产出的 JSP、前端等）
先重跑生成器并跑项目自带校验（静态检查、断言）全绿再打包——陈旧或带缺陷的产物打出去
就是线上故障。

中文路径在 PowerShell 下有编码风险：暂存目录、打包输出目录与 `-Name` 一律用纯 ASCII
（如 `-OutDir C:\Temp\drill-order-ledger`、`-Name order-ledger-full`；用户名含中文时
`%TEMP%` 同样不合格）。输出默认 = 项目输出目录；本流程一律用 `-OutDir` 落到纯 ASCII
演练目录（见步骤 4），打包与假根演练都用这一份；演练通过后再拷回项目输出目录留档——
交付到服务器的、留在输出目录的、步骤 10 报告哈希的，都是同一个 zip。脚本不拦 `.java`，
误指源码目录会把源码打进包。

```powershell
cd deploy-kit
.\New-DeployPackage.ps1 -SourceRoot <编译产物目录或暂存目录> `
    -MapFile .\maps\<项目>-full-baseline.map -Name <项目简名>-full `
    -OutDir C:\Temp\<演练目录>
```

（传了非默认 `-OutDir`，脚本会打印黄色提示——演练/ASCII 落点属预期，直接继续。）
脚本自校验：清单行格式、目标路径相对且无 `..`、不与随包文件重名、源文件在源根内、
目标路径去重、源文件存在。
**完成标准：脚本无报错、zip 产出（解包核对归步骤 4 第 1 条，本步不重复）。**

### 4. 假根演练（不碰真实 ecology）

对步骤 3 产出的**这一份** zip 在 `C:\Temp\<演练目录>\` 内闭环五步——全程用它，交付的也是它。
先建**空目录** `<演练目录>\fake-eco\`：它就是假 ecology 根（install.bat 要求根目录已存在，
否则直接退出码 1）；zip 解包到同级 `pkg\` 子目录，全部命令在 `pkg\` 内执行。

1. 解包并记录 zip SHA256：manifest.txt 行数 = 基线有效行数；包内每个文件 SHA256 == manifest == 来源（三方一致）；
2. 假根安装：`install.bat <假 ecology 根>` → 全 `[OK]`、退出码 0；
3. 假根 `/verify` → 退出码 0；
4. **篡改假根里一个文件再跑 `/verify` → 必须退出码 1**（证明审计真的在查，而非永远绿灯）；
5. 重装恢复：再装一次 → 安装退出码 0，`/verify` 亦退出码 0。

**完成标准：五步全过；把这一份 zip 拷回项目输出目录留档（交付、留档、报告哈希都是它）。**

### 5. 拷贝到服务器并解压

步骤 5–9 在 ecology 服务器上执行：本会话能直连服务器就自己执行并取证；不能直连时，逐步请
用户执行并把**可核对的原始输出**贴回（install.bat 汇总行与退出码、日志与失败清单的完整路径、
`/verify` 结果），未拿到原始输出不得判定该步完成。

zip 整包拷贝到 ecology 服务器，解压到独立目录（如 `D:\temp\<包名>\`）并进入该目录。
**完成标准：服务器上 manifest.txt 与 files\ 同目录就位。**

### 6. 确认门（安装前，必过）

向用户复述四件事并等明确确认：

1. 服务器 ecology 根目录为 <实际路径>（本次一律显式传参；默认值 `D:\WEAVER\ecology` 很可能
   正是真实安装）；
2. 本次文件数（zip 内 files\ 数量，应等于基线有效行数）与覆盖清单：其中 <N> 个是**覆盖
   既有文件**（按清单头部「覆盖既有」行复述文件名——安装前自动备份），其余为新增；
3. 备份目录将建在 `<解压目录>\_backup\<时间戳>\`（回滚锚点，自 v2.0 起不再放 ecology 根下，
   避免被 ecology 扫描影响启动）；
4. 稍后重启将清空全部在线会话，相关方需重新登录。

**完成标准：用户明确确认后才进入第 7 步。**

### 7. 服务器安装

```
install.bat <服务器ecology根>
```

流程：装前自检（逐个核对包内文件与 manifest 一致，不一致立即中止、不动目标）→ 备份旧文件 → 按 manifest 逐个复制 → certutil 逐文件复核 SHA256 → 汇总。
命令行模式无交互：**清单含 jar 包时，安装前必须向用户确认 ecology 服务已停止**
（jar 的 yes 确认与批量 jar 强制手动路径只在菜单模式有；命令行模式根目录由本步显式
传参，不受批量 jar 规则约束）。
退出码 0 = 全部通过；1 = 有失败或用法/环境错误（根目录不存在、缺 manifest.txt /
files 目录、缺 certutil、manifest 非法行，逐条报错，不静默跳过）。全部操作写入
`<解压目录>\logs\deploy_<时间戳>.log`（CLI 模式不回显日志路径，取 `<解压目录>\logs\`
下最新的 `deploy_*.log`）。失败先回滚再排查（用菜单回滚或手工从 `<解压目录>\_backup\
<时间戳>\` 恢复）；排查期间保留备份目录，它是回滚锚点。
**完成标准：退出码 0、汇总"失败 0 个"，记录备份目录完整路径与日志文件路径。**

### 8. 重启正式服务（重启前再次确认）

重启前向用户确认一条：将清空全部在线会话，相关方需重新登录；得到明确确认后再执行。

`net stop "ecology"` / `net start "ecology"`（服务名以服务器 services.msc 实际为准）。
Jersey 只在 webapp 启动时扫 `com.cloudstore;com.api` 包，不重启 = 新类永远不注册。
**完成标准：`net start` 输出服务已启动（必要时 `sc query "ecology"` 显示 RUNNING），且已请
用户通知相关方重新登录（用户确认即可）。**

### 9. 审计与业务复核

1. 审计：服务器上 `install.bat <服务器ecology根> /verify` → 全 `[OK]`、退出码 0；
   有失败时清单在 `<解压目录>\logs\verify_fail_<时间戳>.txt`，可直接转发开发；
2. 业务探针：已登录会话的浏览器打核心接口（fetch + `credentials:'include'`——鉴权
   只认 session，无 token 通道），断言状态码与 `api_status`/`api_errormsg`；
   无现成登录会话时，用可用的浏览器工具（如 agent-browser）打开登录页、由用户完成登录后
   再执行探针；或请用户在其已登录浏览器里执行并把结果贴回。
3. **版本判据**：探针至少断言本轮产物的线上特征（新增 DOM/行为/字段）——否则"通过"
   可能属于旧版本；版本存疑时先在页面内断言这些特征，直接拉页面源可能被登录/门户导航截胡。
**完成标准：/verify 退出码 0 + 探针断言通过（含版本判据）。**
不通过 → 先按回滚流程恢复（见 `deploy-kit\README.txt` §七），保留现场再排查。

### 10. 报告

向用户报告五项：包名与文件数（附 zip 与关键文件 SHA256）、服务器 ecology 根、备份目录完整
路径（回滚锚点）、假根演练结论与安装后审计/探针结果、包外需另行配置的项（如 OA 后台菜单
入口；无则说明无）。
**完成标准：五项已报告；本次记录（清单文件名、部署时间、服务器根、备份目录）已追加写回
`deploy-kit\projects.md` 中该项目的「最近部署」列。**

## 回滚

首选用菜单回滚（install.bat 主菜单输入 3）：选回滚点 → 输 ecology 根 → 自动恢复旧文件
并按提示删除当次新增文件。手工备选：从 `<解压目录>\_backup\<时间戳>\` 按原相对路径拷回 →
重启服务 → `/verify` 复核。当次新增文件记录在 `_newfiles.txt`，回滚时据此删除。
细节见 `deploy-kit\README.txt` §七。

## 红线

- **本技能文件是公开仓库的发布物**：真实项目名、真实路径、服务器信息一律不得写进本文件或
  `.agents\skills\` 下任何文件；项目数据只落 `deploy-kit\` 下的本机文件（`projects.md`、
  `maps\`、`deploy-config.json`），这些已被 `.gitignore` 忽略。
- 正式环境一律显式传服务器实际 ecology 根：命令行模式省略根时会取 `ECOLOGY_ROOT` 环境变量
  或默认 `D:\WEAVER\ecology`，**无确认直接安装**，默认值很可能正是真实安装目录
  （历史上发生过误写事故）。
- 基线外文件一律先人工 review 再并入（见步骤 1）；清单永远逐行显式，不照抄目录。
- **打包后不得再改包内文件**（含用压缩工具编辑 zip 内容）：manifest 是打包时算的，改包会让包自相矛盾，install.bat 装前自检会直接拒绝。需改内容就改源/暂存目录后重新打包。
- 假根演练一律在纯 ASCII 目录（如 `C:\Temp\`）内闭环（见步骤 4）：不碰真实 ecology、
  不重启任何服务；真实服务器拷贝与正式服务重启只发生在真实部署中。

打包/安装的 FAQ、编码兼容说明、回滚细节见 `deploy-kit\README.txt`；术语见工作区根 `GLOSSARY.md`。

## 询问用户规范（内置，不依赖外部技能）

本技能面向任意使用环境，自包含询问交互。文件目录、目标路径、清单条目等**不是固定值**，
遇到不确定信息时**禁止猜测**，按以下规范主动向用户提问确认后再继续：

1. **先列事实再提问**：把我已从环境查明的事实（文件是否在场、目录结构、已有配置）摆出来，
   用户只需补我不知道的决策，不让用户做我能自己查的事。
2. **带推荐答案**：每个问题给出我的推荐选项并说明理由，用户回"同意"即可推进；
   推荐项永远放在第一位并标注"（推荐）"。
3. **一次问整轮**：把当前不依赖其他答案的全部待定点一次问完，逐题编号；用户答完再推进
   下一轮（依赖已答项的问题留到下一轮）。
4. **典型必须询问的场景**：
   - ecology 根目录、编译输出根、暂存目录路径不确定时；
   - 基线清单之外发现新文件、是否并入不确定时；
   - 部署目标（测试 / 正式）、包名、输出目录不确定时；
   - 任何"照抄整目录"的冲动——改为逐行枚举并请用户确认。
5. **交互边界**：菜单交互（回滚点选择、jar 停服确认、路径输入）只在用户手动运行时
   发生；本技能的命令行调用不经过菜单，相关确认由我在调用前向用户提出。菜单是为人在
   控制台操作设计的——用管道喂输入会被 cmd 一次读走整段（不是逐行），非交互场景一律走
   命令行模式。
