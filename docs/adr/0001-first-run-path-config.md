# 首跑路径配置由技能引导生成，而非手改模板文件

## Status

accepted

模板工具包对外发布时不能携带任何真实机器路径，而部署流程又必须知道 ecology 安装根。
我们选择：技能**首次调用**时弹出选择栏询问一次（服务器默认路径 `D:\WEAVER\ecology`
或自定义可复用路径），确认后写入 `deploy-kit\deploy-config.json`（含 confirmed 标记），
此后所有调用直接读配置、不再询问。

被否方案：

- 在 SKILL.md 里留一张"符号表"由使用者手工编辑——模板将携带真实路径（发布即泄漏），
  且改文件易错、两份 SKILL.md 易漏改其一；
- 每次会话都询问——对日常迭代是打扰，且答案几乎不变。

## Consequences

- `deploy-config.json` 属本机状态，必须进 `.gitignore`，不得随仓库发布；
- 两个技能各自实现同一段"读配置 → 缺失则询问 → 写配置"逻辑（技能独立调用，各自必须
  自包含，允许这点小重复）；
- 用户取消询问时不写配置，下次调用仍会询问。

## 后续修订（2026-10-13）

选项标签由「服务器默认路径 / 可复用路径」改为「本机 ecology 安装根 / 自定义安装根」，并在
两个技能里写明：登记的根是**本机部署目标**，本机若同时装着生产 ecology 必须分开确认、
不得把生产根登记为部署目标（原标签容易被读成"这就是服务器上的根"）。决策本身未变。
