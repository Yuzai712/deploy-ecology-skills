# install.bat 回归纯批处理：移除 PowerShell 关窗 hack，防线前移到装前自检

## Status

accepted

v2.0 为「尽量禁止用户直接点 X 关窗」在 install.bat 里加了 `:trylockclose`：以
`powershell -WindowStyle Hidden` 现场 `Add-Type` 编译 C# 并 `DllImport user32` 操作窗口菜单。
该段在生产服务器上表现为双击后窗口瞬间消失（日志只写到日志初始化头部），本地无法复现。

我们选择：整段移除，install.bat 回到纯批处理；关窗只保留菜单底部常驻文字提示（用 `q` 退出）。
同一轮把防线前移到「装前」：新增 `:selfcheck_payload`，安装前逐个核对包内文件与 manifest，
不一致立即中止且不动目标文件。

被否方案：

- 保留但加开关（先探测 PowerShell 是否存在）——隐藏窗口 + 现场编译 + 操作窗口菜单这个组合
  本身就可能被 EDR / 杀软终止，留在生产脚本里风险不可控；
- 彻底不管关窗——脚本无法禁用关闭按钮，只能靠提示，这与 v2.0 之前的行为一致，可接受。

## Consequences

- 服务器端依赖收窄为 cmd 内建命令 + `certutil`：不依赖 PowerShell，也不会被安全软件按
  「脚本内联编译」拦下；
- 关窗保护降级为文字提示，属已知取舍；
- 包内文件与 manifest 不一致（典型成因：打包后又手工改过包内文件）在安装前即被拦截，
  由此立下红线「打包后不得再改包内文件」，要改就改源/暂存目录后重新打包；
- 菜单在 stdin 非交互（EOF）时的刷屏也一并加了护栏：连续 20 次空输入即退出。
